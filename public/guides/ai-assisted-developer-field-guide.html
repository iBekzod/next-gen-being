The one idea that changes everything

Most people use AI like a vending machine: type a request, grab whatever falls out. The developers who get 10× results treat it like a junior pair-programmer with infinite patience — they give it context, constrain it, review its work, and iterate.

Everything below is downstream of that shift: context and constraints beat clever prompts.

The 4-step loop I run for every task

1Frame

Before writing a prompt, write the spec. What's the input, the output, the constraints, the definition of done? A model can't read your mind — but it will faithfully build the wrong thing if you let it guess.

2Ground

Paste the real context: the actual file, the error, the surrounding code, the versions. Generic answers come from generic prompts. The single biggest quality jump is giving the model your real code instead of describing it.

3Constrain

Tell it what NOT to do. "Match the existing style." "No new dependencies." "Return only the diff." Constraints are what turn a plausible answer into a usable one.

4Verify

Never ship what you can't verify. Run it. Read it. Ask the model to critique its own output ("what edge cases does this miss?"). AI removes the typing, not the responsibility.

5 prompts worth stealing

1 · The reviewer

Review this code as a skeptical senior engineer.
List concrete bugs, edge cases, and security issues —
most severe first. Don't praise it. Show the failing input.

2 · The explainer

Explain what this code actually does, line by line,
then tell me the ONE thing most likely to break in production.

3 · The refactor (surgical)

Refactor for readability WITHOUT changing behaviour.
Keep the same public API. Return only a diff.
If a change is risky, flag it instead of making it.

4 · The test writer

Write tests for this function. Cover the happy path,
boundaries, and the failure modes. Name each test
after the behaviour it proves, not the method it calls.

5 · The rubber duck

I'm stuck. Here's the goal, what I tried, and the error.
Ask me 3 clarifying questions before proposing a fix.

Choosing tools without drowning

There are a thousand AI tools. You need a handful. The test is simple:

A tool earns its subscription only if it saves more time (or makes more money) than it costs — every month. Everything else gets cancelled.

Don't collect tools. Collect workflows. One tool you've mastered beats ten you've dabbled in. Pick one for code, one for writing, one for automation — go deep before you go wide.

The mistakes that cost me the most time

  • Trusting confident output. Fluent ≠ correct. Verify.
  • Vague prompts. Ten minutes framing saves an hour of re-prompting.
  • No context. Describing code instead of pasting it.
  • Letting it invent APIs. Always check the docs it cites are real.
  • Big-bang generation. Small, verifiable steps beat one giant blob.
